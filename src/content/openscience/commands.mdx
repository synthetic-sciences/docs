The OpenScience command surface. For live help, run `openscience --help` and `openscience <command> --help`.

The bare `openscience` (no arguments) starts the local server and opens the **browser workspace** in your working directory. Everything else is grouped below.

## Global flags

| Flag | Use |
| --- | --- |
| `-v, --version` | Print the installed version. |
| `-h, --help` | Print help for a command. |
| `--print-logs` | Stream agent diagnostics to stderr. |
| `--log-level <DEBUG\|INFO\|WARN\|ERROR>` | Override the log threshold. |

## Workspace and runs

| Command | Use |
| --- | --- |
| `openscience` | Start the server and open the browser workspace. |
| `openscience run [message..]` | One-shot prompt in the terminal; streams, then exits. |
| `openscience session list` | List recent sessions (`-n`, `--format`). |

`run` flags: `-c/--continue`, `-s/--session <id>`, `-m/--model <provider/model>`, `--variant <high|max|minimal>` (provider-specific reasoning effort), `--agent <name>`, `--format <default|json>`, `-f/--file <path>`, `--attach <url>` (attach to a running server, e.g. `http://localhost:4096`), `--port`, `--title <text>`.

```bash
openscience run "Plot the attention entropy across layers for this checkpoint"
openscience run -c "Now sweep the temperature and re-plot"
openscience run --format json "Summarize the experiment in results/" > summary.json
```

## Account

Connecting an Atlas account is optional. See [Connect to Atlas](/openscience/atlas). OpenScience also runs with your own provider keys or local models.

| Command | Use |
| --- | --- |
| `openscience init` | Run the setup wizard. Choose managed models, your own keys, or skip model setup. Alias: `onboard`. |
| `openscience login` | Connect your Atlas account (browser flow, or `--key thk_…`). |
| `openscience status` | Show the Atlas account, synced services, subscription, wallet, recent usage, compute availability, and bundled `atlas` version. Alias: `whoami`. |
| `openscience sync` | Re-pull synced credentials. |
| `openscience devices` | List authorized devices. |
| `openscience logout` | Disconnect this device from Atlas. |
| `openscience doctor` | Report what's configured: account, provider keys, wallet, default model. |

`openscience connect …` still works as an alias for `login` / `logout` / `status` / `sync` / `devices`.

## Providers and routing

| Command | Use |
| --- | --- |
| `openscience keys add` | Add a provider API key (BYOK; OAuth sign-in where supported). Alias: `auth`. |
| `openscience keys signin` | Sign in with ChatGPT / Codex (subscription). |
| `openscience keys list` | List saved provider keys and active env vars. |
| `openscience keys rm` | Remove a saved provider key. |
| `openscience models` | List configured providers and their models. |
| `openscience local add` | Detect and register Ollama, LM Studio, or another OpenAI-compatible endpoint. |
| `openscience local list` | List configured local providers. |
| `openscience local remove <id>` | Remove a local provider from config. |
| `openscience wallet` | Wallet balance and key routing (alias `billing`). |
| `openscience wallet topup` | Open the app to add credit. |

## Sandbox

| Command | Use |
| --- | --- |
| `openscience sandbox` | Show sandbox status: OS backend + current policy. |
| `openscience sandbox enable` | Confine the agent's shell + notebook execution to the workspace (`--network deny`, `--allow <path>`, `--on-unavailable <warn\|error\|allow>`). |
| `openscience sandbox disable` | Turn the sandbox off. |
| `openscience sandbox test` | Prove containment on this machine (writes inside/outside the workspace, network egress). |

Off by default. See [Execution sandbox](/openscience/sandbox).

## Agent profiles

| Command | Use |
| --- | --- |
| `openscience agent list` | Print the agent roster on this install. |
| `openscience agent create` | Scaffold a custom agent (system prompt + tool set + routing policy). |

Flags: `--path`, `--description`, `--mode <all\|primary\|subagent>`, `--tools`, `--model`. See [Agents](/openscience/agents).

## Skills

| Command | Use |
| --- | --- |
| `openscience skill list` | Show installed skills (`--all` for the bundled set). |
| `openscience skill show <name>` | Print a skill's metadata and entrypoints. |
| `openscience skill add <url-or-name>` | Install a skill (URL or `gh:owner/repo`). |
| `openscience skill new` / `edit` / `validate` | Author, edit, and check user skills. |
| `openscience skill remove <name>` | Uninstall a skill. |
| `openscience skill set-entries <name>` | Update which skills surface in the `/` picker. |

## Local server and protocols

| Command | Use |
| --- | --- |
| `openscience web` | Start the server and open the browser workspace (prints the URL, e.g. `http://localhost:4096`). |
| `openscience serve` | Start a headless local server on `127.0.0.1` without opening a browser. |
| `openscience acp` | Start an Agent Client Protocol server for editors like Zed. |
| `openscience mcp` | Manage MCP servers (`list`, `add`, `remove`, `auth`). |

`web` and `serve` take `--port` and `--cors`. See [Workspace](/openscience/workspace).

## Agent-facing research tools

These capabilities run inside an agent session rather than as shell subcommands:

| Tool family | Use |
| --- | --- |
| `science_list_dbs`, `science_search`, `science_fetch` | Discover 42 scientific sources, search them, and retrieve structured records or supported files. See [Scientific data](/openscience/scientific-data). |
| `modal`, `compute_job` | Review and dispatch governed Modal work, then inspect logs, outputs, cancellation, and retained-output recovery. See [Compute](/openscience/compute). |
| `provenance_record`, `provenance_query`, `provenance_review` | Record outputs and runs, trace lineage, and attach supporting or refuting review findings. See [Artifacts & provenance](/openscience/artifacts). |

Cloud provider work is skill-driven. OpenScience bundles skills for Lambda Labs, TensorPool, Modal, and SkyPilot. SkyPilot covers AWS, Google Cloud, Azure, Kubernetes, Lambda Cloud, RunPod, and other supported backends. See [Compute](/openscience/compute) for native versus skill-driven execution.

## GitHub and PRs

| Command | Use |
| --- | --- |
| `openscience github` | GitHub agent for CI/Actions (`install`, `run`). |
| `openscience pr <number>` | Check out a PR branch, then launch the agent on it. |

## Project and lifecycle

| Command | Use |
| --- | --- |
| `openscience project` | Pin the Atlas project root for this folder (`merge`). |
| `openscience export` / `openscience import` | Export or import a session as JSON. |
| `openscience generate` | Emit the OpenAPI spec for the local server to stdout. |
| `openscience stats` | Local token-usage and cost stats. |
| `openscience debug` | Structured diagnostics for support (`debug paths` shows data/config dirs). |
| `openscience upgrade` | Update to the latest version. |
| `openscience uninstall` | Remove the binary and local config. |
| `openscience completion` | Shell completion for bash, zsh, or fish. |

```bash
openscience upgrade
openscience completion zsh > ~/.zsh/completions/_openscience
```
