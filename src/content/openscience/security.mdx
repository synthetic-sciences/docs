OpenScience is open source under Apache-2.0, so the whole security model below is auditable in the [repository](https://github.com/synthetic-sciences/openscience). The agent runs locally with the same filesystem and shell access you have. Two principles anchor the design: keep credentials out of subprocesses that do not need them, and make the trust boundary explicit instead of pretending the agent is a sandbox.

## The agent is not a sandbox by default

The permission system prompts before selected commands and file writes. It records intent but does not isolate the process. By default, the agent can read, write, and execute anywhere your user can.

The optional [execution sandbox](/openscience/sandbox) wraps shell commands with macOS Seatbelt or Linux bubblewrap. It can confine writes to the workspace and deny network egress. Enable it with `openscience sandbox enable` and verify it with `openscience sandbox test`. For hostile code, use a container or VM as well.

## Credential storage

| Surface | Where | Notes |
| --- | --- | --- |
| BYOK provider keys | Environment variables or the local credential store | Never leave your machine; requests go straight to the provider. No account required. |
| Atlas session | `~/.config/openscience/config.json` | `thk_*` key created by `openscience login`; revocable from the dashboard. |
| Synced service credentials | `~/.config/openscience/credentials.json` | Present only when [connected to Atlas](/openscience/atlas); refresh with `openscience sync`. |
| Native binary (curl install) | `~/.openscience/bin/openscience` | Added to PATH through your shell rc. |

Override the config parent directory with `XDG_CONFIG_HOME`. Run `openscience debug paths` to print the resolved data, config, cache, and state directories on your machine.

## Subprocess environment allow-list

When the agent shells out, it rebuilds the subprocess environment from a curated allow-list rather than inheriting your full shell. Provider keys stay out of commands that have no business seeing them.

**Always passed through:** `PATH`, `HOME`, `USER`, `SHELL`, `TERM`, `LANG`, `LC_*`, `TMPDIR`, `XDG_*`, `EDITOR`, `VISUAL`.

**Passed only to approved subprocesses that need them:** AWS, Google Cloud, Azure, Hugging Face, W&B, Lambda Labs, RunPod, Prime Intellect, TensorPool, Vast.ai, Tinker, LangSmith, Pinecone, and similar service credentials from the allowlist.

**Never passed to the agent shell:** Modal token ids and secrets. The native Modal adapter resolves them only after an approved execution plan.

**Explicitly filtered out, even if set in your shell:** provider credentials such as `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, `GEMINI_API_KEY`, `XAI_API_KEY`, and `META_MODEL_API_KEY`. The agent talks to model providers itself; subprocesses do not need these keys.

## Output redaction

Known credential patterns are redacted from agent output before it lands in a transcript. If you spot an unredacted secret, report it (see below).

## Server mode

Server mode is opt-in. The server binds to `127.0.0.1` and enforces Host and Origin allowlists to block DNS rebinding and cross-origin requests. It is not designed for public exposure. Do not place it behind a public tunnel or reverse proxy without adding your own authentication and network controls.

## What leaves your machine

- Prompts, attachments, and responses sent to the selected model provider.
- Queries sent to scientific databases, literature services, web pages, or MCP servers used in the session.
- Files explicitly uploaded to an approved compute job or external service.
- Credential sync, graph writes, and usage records when you [connect to Atlas](/openscience/atlas).

Project files otherwise remain local. Environment variables outside the subprocess allowlist are not forwarded.

## Reporting a vulnerability

Report security issues through the GitHub Security Advisory ["Report a Vulnerability"](https://github.com/synthetic-sciences/openscience/security/advisories/new) form, not a public issue. If you do not hear back within six business days, email security@syntheticsciences.ai.
