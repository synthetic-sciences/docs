OpenScience gives the agent one consistent interface to 42 public scientific data sources. The connectors cover proteins and structures, genomics, chemistry, pathways and interactions, literature, and omics. Most work without an API key; a source that requires a credential or temporarily rate-limits returns an actionable degraded result instead of crashing the session.

You do not need to learn 42 APIs. Ask for the scientific outcome and the agent discovers the right source, searches it, and retrieves the record or file it needs.

```text
Find structures for the SARS-CoV-2 main protease, retrieve the best experimental
structure as CIF, and summarize the bound ligand and experimental method.
```

## The three-tool flow

| Tool | What it does |
| --- | --- |
| `science_list_dbs` | Lists every available connector, grouped by domain, including supported downloadable formats. |
| `science_search` | Searches one connector and returns normalized ids, titles, summaries, scores, and source URLs. |
| `science_fetch` | Retrieves one result by id as a structured record or supported file format. |

The agent normally calls these tools for you. The separation is deliberate: search finds the stable source id, while fetch retrieves the complete record without guessing from a search-result snippet.

## Connector catalog

| Domain | Sources |
| --- | --- |
| Proteins and structures | UniProt, RCSB PDB, PDBe, AlphaFold DB, InterPro, Pfam, SIFTS |
| Genomics | Ensembl, NCBI Gene, dbSNP, ClinVar, gnomAD, UCSC, MyGene, MyVariant |
| Chemistry | ChEMBL, PubChem, BindingDB, Guide to Pharmacology, SureChEMBL, ChEBI |
| Pathways and interactions | Reactome, KEGG, STRING, BioGRID, IntAct, WikiPathways, Open Targets |
| Literature | PubMed, Europe PMC, bioRxiv, Crossref, OpenAlex, Semantic Scholar, arXiv |
| Omics | GEO, ArrayExpress, GTEx, Human Protein Atlas, Expression Atlas, Single Cell Expression Atlas, DepMap |

The live catalog is authoritative. Connector availability and supported formats are exposed by `science_list_dbs`, so the agent does not need to guess.

## Retrieve scientific files

Seven connectors expose common research file formats directly:

| Source | Formats |
| --- | --- |
| RCSB PDB | `pdb`, `cif` |
| PDBe | `cif` |
| AlphaFold DB | `pdb`, `cif` |
| UniProt | `fasta`, `txt` |
| PubChem | `sdf` |
| Ensembl | `fasta` |
| KEGG | `fasta` |

For example, the agent can search RCSB PDB, take the selected hit id, and call `science_fetch` with `format: "cif"`. Downloaded structures, sequences, and molecules land in the project and can open in the workspace's scientific viewers.

## Large-record handling

OpenScience measures the serialized record at runtime instead of assuming that one connector is always small or large.

- Records up to 50 KiB return inline to the agent.
- Larger records and all downloaded files spill to `.openscience/fetch/<source>/`.
- Spill filenames are sanitized for macOS, Linux, and Windows.
- The tool returns the path, byte count, and a compact summary, then the agent can read or render the file.
- The fetch directory ignores its generated contents in git, so retrieval does not pollute `git status`.

Writing a spilled result still crosses the normal file-edit permission boundary.

## Failure behavior

A source outage is not the same as an empty result. The connector layer keeps those cases distinct:

| Condition | What the agent receives |
| --- | --- |
| No matching record | A clean miss with a zero result count. |
| Unknown source or unsupported format | The available source ids or formats. |
| Rate limit or transient outage | Retry guidance and a structured `rate_limited` result. |
| Other upstream error | A structured `source_error` with the source message preserved. |

This lets a long research session degrade gracefully, try another source, or retry later without mistaking an API failure for scientific evidence that nothing exists.
