OpenScience works without an account. With your own provider keys, requests go directly to the providers you choose. [Atlas](/atlas/index) is optional.

## What connecting adds

- **Managed models.** Use supported models through a prepaid wallet instead of maintaining a separate key for each provider. The default endpoint is `app.syntheticsciences.ai`; `OPENSCIENCE_API_BASE` overrides it.
- **Billing controls.** Choose managed or BYOK routing separately for models and compute in **Settings > Billing**.
- **Credential sync.** Store supported cloud, data, and ML service credentials on your account and pull them to another machine.
- **Research graphs.** Record hypotheses, runs, evidence, and decisions in [Atlas](/atlas/index).
- **GPU marketplace.** Compare live Lambda Labs, RunPod, Vast.ai, and Prime Intellect VM offers in the Atlas Compute page.

## Link your account

<Steps>
  <Step title="Log in">
    ```bash
    openscience login
    ```

    Opens your browser to approve the device. On headless or CI machines, pass `--no-browser` and paste a key, or run `openscience login --key thk_...` with a key created at `app.syntheticsciences.ai/cli`.
  </Step>
  <Step title="Verify">
    ```bash
    openscience status
    ```

    Prints the connected user and device, credential sync status, wallet balance, recent usage, managed compute availability, and the bundled `atlas` CLI version.
  </Step>
  <Step title="Sync credentials">
    ```bash
    openscience sync
    ```

    Refreshes synced service credentials after you change them on the dashboard.
  </Step>
</Steps>

## Model routing and billing

Key routing is per-provider and automatic: if you set a BYOK key for a provider, OpenScience uses it; otherwise the request goes through the Atlas managed route and debits your wallet.

```bash
openscience wallet         # wallet balance and current key routing
openscience wallet topup   # open the Plan tab to add wallet credit
```

Flip managed versus BYOK per surface (LLM and compute) in **Settings → Billing**. BYOK works on every plan.

## Where credentials live

After login, the account holds the canonical copy of each synced credential. The local `~/.config/openscience/credentials.json` file is a mirror that `openscience sync` can rebuild. Provider keys saved only in local BYOK mode stay on the machine. See [Security](/openscience/security) for storage and subprocess rules.

## Account commands

| Command | Use |
| --- | --- |
| `openscience login` | Authenticate via browser; `--key thk_...` or `--no-browser` for headless machines. |
| `openscience status` | Connection, user, device, and synced credential count. |
| `openscience sync` | Re-pull synced service credentials from the dashboard. |
| `openscience devices` | List authenticated devices; revoke from the Devices tab on the dashboard. |
| `openscience logout` | Disconnect this machine. BYOK keeps working. |
