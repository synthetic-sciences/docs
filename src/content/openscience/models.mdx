OpenScience is model-agnostic. A **model** is an inference endpoint. A **provider** exposes one or more models. With your own key, each request goes directly from your machine to that provider. No account or OpenScience gateway is involved.

## Bring your own keys

Set a key from any provider and start working:

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # or OPENAI_API_KEY, GEMINI_API_KEY, ...
openscience
```

Keys stay on your machine. Anthropic, OpenAI, Google, OpenRouter, Groq, Mistral, xAI, Meta Model API, DeepSeek, and other models.dev providers use the same `provider/model` naming scheme. You can paste keys into the Credentials panel instead of exporting them. Supported subscription-based OpenAI models can also use the OAuth sign-in flow.

The current frontier families are available on both paths:

| Family | BYOK model | Atlas managed model |
| --- | --- | --- |
| GPT-5.6 Sol / Terra / Luna | `openai/gpt-5.6-*` | `openrouter/openai/gpt-5.6-*` |
| Grok 4.5 | `xai/grok-4.5` | `openrouter/x-ai/grok-4.5` |
| Muse Spark 1.1 | `meta/muse-spark-1.1` | `meta/muse-spark-1.1` through the Atlas Meta proxy |

For BYOK, use `OPENAI_API_KEY`, `XAI_API_KEY`, or `META_MODEL_API_KEY`. The managed Meta route sends only your Atlas session token and proxy URL to OpenScience; Atlas keeps its shared Meta credential server-side.

Current frontier families include:

| Provider | Model IDs |
| --- | --- |
| Anthropic | `claude-opus-5`, `claude-sonnet-5` |
| OpenAI | `gpt-5.6`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` |
| xAI | `grok-4.5`, `grok-4.3`, `grok-build-0.1`, and Grok 4.20 reasoning, non-reasoning, and multi-agent models |
| Moonshot AI | `kimi-k3` |
| Vercel AI Gateway | `meta/muse-spark-1.1` |

This is not a hardcoded allowlist for your own provider keys. OpenScience refreshes models.dev at startup and hourly, so newly published models appear without waiting for an OpenScience release. The OpenAI Codex OAuth provider is the exception: it only shows models verified to work through a ChatGPT subscription, currently including the full GPT-5.6 family.

## Local models

OpenScience also connects to local OpenAI-compatible endpoints such as Ollama, LM Studio, llama.cpp, and vLLM:

```bash
openscience local add        # detects Ollama / LM Studio, lists + adds their models
openscience run --model ollama/llama3.1 "hello"
```

Local models are free and never metered. See **[Local models](/openscience/local-models)** for the full guide.

## List what is configured

```bash
openscience models             # grouped by provider, with a routing label per provider
openscience models anthropic   # one provider
```

Each provider is labeled `your key`, `managed`, `local`, `Signed in with Codex`, or `unconfigured`, so you always know which route a model takes. `--verbose` adds per-model metadata like costs, `--refresh` refetches the catalogue, and `--flat` prints one `provider/model` id per line for scripting.

## Pick a model per run

```bash
openscience run --model anthropic/claude-opus-5 --variant xhigh "Design the ablation study"
openscience run --model anthropic/claude-sonnet-5 "Clean up the plotting code"
openscience run --model openai/gpt-5.6-terra --variant max "Review the analysis"
openscience run --model moonshotai/kimi-k3 "Implement the pipeline"
```

`--model <provider>/<model>` overrides the default for one run. In the workspace, use the model selector per session. `--variant` picks a provider-supported reasoning tier such as `minimal`, `high`, `xhigh`, or `max`. The available tiers depend on the model.

## Atlas managed (optional)

[Atlas](/atlas/index) is the managed platform. Connecting adds a curated set of frontier models billed from a prepaid wallet, so you can skip per-provider keys entirely:

```bash
openscience login   # defaults to app.syntheticsciences.ai
```

After login, the workspace can sync provider configuration and credentials. **Settings > Billing** controls managed or BYOK routing separately for models and compute. Atlas meters only requests and resources it serves.

| Path | What runs where | Billing |
| --- | --- | --- |
| BYOK (default) | Your machine calls the provider directly. | Your provider account. |
| Atlas managed | Your machine calls Atlas, which calls the provider. | Prepaid wallet. See [Atlas billing](/atlas/billing). |

## Key hygiene

Provider keys and synced credentials are filtered out of the environment of every subprocess the agent spawns and redacted from output. The agent talks to providers itself; the code it runs never needs your keys. Credentials are stored per user in your home directory, never in the project's `.openscience/` directory, so they cannot end up in a commit. See [Security](/openscience/security).
